# Commit message

1. Run `git status --short` and `git diff --staged` (if nothing is staged, `git diff`). Read every hunk; do not guess from file names.
2. Check the project's history for its style: `git log --oneline -15`. Match it (prefix conventions, ticket references, casing).
3. Write: a subject of at most 72 characters in the imperative ("Fix the retry loop", not "Fixed"), a blank line, then a body that says *why* the change was made and what was deliberately left out. Skip the body for trivial changes.
4. If the change mixes unrelated things, say so and propose splitting it into separate commits instead of one vague message.
5. Never add co-author or "generated by" trailers unless the project's own instructions ask for them. Show the message; only run `git commit` when the user says to.
