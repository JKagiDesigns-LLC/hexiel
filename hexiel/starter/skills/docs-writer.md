# Docs writer

1. Read the code and any existing docs. Decide the reader (new user, integrator, maintainer) and write for them only.
2. Structure: one-sentence purpose, quick start (the shortest path to a working result), the common tasks, reference (options, endpoints, config), troubleshooting.
3. Every command and code sample must be run or checked against the code before it goes in; paste real output. Flag anything you could not verify.
4. Prefer short sections, concrete examples and exact names. Update existing docs in place instead of adding a second competing file.
